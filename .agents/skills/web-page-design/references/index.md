与 O Chat 产品参考分开维护。当前两张都是 2026-09-27（Australia/Sydney）从官方网页实际捕获的桌面首屏，1440 × 1000 CSS px、DPR 1、英文、无登录、reduced motion。它们用于研究表达与构图，并非手机或交互验收样本。

## W01 · 让文字与产品证据共用一个阅读方向

观察大标题左边缘、解释文字和下方界面演示形成的顺序。迁移到自己的页面时，用真实界面或产物证明标题所说的价值，保证裁切后仍看得出产品用途。

适用：产品定位明确、已有具体界面的介绍页。局限：首屏主行动位于顶部导航，未必适合需要立即转化的新产品；本次捕获未验证转化效果。不要复制其深色、文案或大标题尺寸作为品牌。

比较：我们能否在第一屏读懂用途、看到证据、找到下一步？演示是具体产品还是模糊的装饰框？

## W02 · 行动与使用条件放在一起

观察居中标题、短说明、单个下载行动、紧邻的系统要求，再到具体任务演示。这个次序让用户在行动前知道适用条件。

适用：单一入口、需要解释平台要求的产品页。局限：演示的窗口、背景与光效服务营销叙事；不应用在长时间使用的聊天工作区。本次捕获不证明下载、演示互动或手机表现。

比较：我们的行动是否明确，必要条件是否及时出现？标题下是否有真实证据，还是继续堆形容词？

## 对照方法

1. 选择一个参考，打开完整本地图，写清想借鉴的可见机制与自身内容差异。
2. 用真实内容生成自己的页面，在可比视口检查标题、证据、行动、对齐、阅读节奏。自己的 before/after 保持同样内容和视口。
3. 分别回答：效果是否达到、相关完成度是否接近、最大的具体差距是什么。图片缩放不提供字号或间距的精确测量。
4. 补充手机及中间尺寸、焦点与实际行动验证。本库没有手机首屏参考；在增加并审阅匹配参考前，不声称手机已达到同样水平。
5. 将结果写到项目报告，使用相邻 `frontend-ui-verify/references/visual-review-record.md`。产品工作区应改用 `oo-chat-product-design`。

新增参考时保留官方 URL、日期、原图、尺寸、捕获方式与校验值，并实际看图。对比的是服务用户任务的效果，不能通过品牌知名度、颜色相似或装饰多寡判定设计合格。
